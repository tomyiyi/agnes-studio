## 第 2 轮（2026-10-01）

**主题**：网关健康检查端点 `/api/gateway/health`（文本/聊天网关的服务端探活）

**改动点**：
1. `scripts/studio_server.py` —— 新增 `probe_gateway(base_url, timeout=5, api_key=None)`：
   - 轻量 `GET <base>/models`，不触发模型推理调用；
   - 成功 / HTTPError / 连接异常收敛为结构化结果（reachable/latency_ms/http_status/model_count/chat_models/image_models），不抛异常；
   - **实跑发现并修正**：本机 New API 的 `/models` 需要鉴权（无 key 返回 401，首版健康检查永远红灯）——改为服务端携带已解析的 key 经 `Authorization: Bearer` 头出站探活；key 绝不进入返回结果/日志/前端。
2. `do_GET` 新增 `/api/gateway/health` 路由：同时探活 chat（`resolve_chat_credentials`）与 image（`resolve_image_base_url` + local 配置 key）网关，返回 checked_at + 两路探活结果。
3. `tests/test_studio_gateway_health.py`（新建，7 个测试）：三种探活路径、无 key 不发 Authorization 头、有 key 时 Bearer 头出站但 key 不进结果、非法 base_url、路由合同。

**测试**：全量 `python -m unittest discover -s tests` —— **492 通过**（含同仓库并行 worker 新增的 16 个 gateway_failover 测试，全部绿），0 失败。

**实跑验证**（本轮真实 New API 调用共 3 次，达限额上限）：
1. 启动 studio_server 临时实例（端口 18099），curl `/api/gateway/health` → chat/image 均 `HTTP 401: Unauthorized`（/models 需鉴权的发现）；
2. 修正后直接调用 `probe_gateway(..., api_key=解析 key)` → `HTTP 200`、`model_count=14`、`latency_ms=17`，`chat_models` 含 `agnes-3.0-flash`，`image_models` 含 `agnes-image-2.0/2.1/2.5-flash`、`dall-e-2/3`；结果中无 key 回显；
3. 临时服务已停止，端口 18099 释放。
